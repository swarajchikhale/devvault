# Contributing to DevVault

Thank you for your interest in contributing to DevVault! 🎉

DevVault is an open-source developer productivity and knowledge platform. We welcome contributions from developers of all experience levels.

Whether you want to fix a bug, improve documentation, add a feature, improve the UI, write tests, or suggest an idea, your contribution is welcome.

## 📋 Before You Start

Before making a contribution:

1. Check the existing [issues](https://github.com/swarajchikhale/devvault/issues) to see if the work is already being discussed.
2. For larger changes, open or discuss an issue before starting implementation.
3. Read this guide and follow the project's development conventions.
4. Keep your changes focused and avoid unrelated modifications.

## 🐛 Reporting Bugs

If you find a bug, please create a GitHub issue and include:

- A clear description of the problem
- Steps to reproduce the issue
- Expected behavior
- Actual behavior
- Relevant screenshots or logs, if applicable
- Your environment and browser/OS information

Please search existing issues before creating a new one to avoid duplicates.

## 💡 Suggesting Features

Feature suggestions are welcome.

When proposing a feature, explain:

- What problem it solves
- Why it would be useful
- How you think it could work
- Any alternative solutions you considered

For large features, please discuss the idea in an issue before starting implementation.

## 🔧 Development Setup

Development setup instructions will be added as the project implementation progresses.

The project will contain:

```text
backend/     → Spring Boot backend
frontend/    → React frontend
docs/        → Project documentation
```

More detailed setup instructions will be maintained in the project documentation.

🌿 Branching

Please create a separate branch for your work.

Use descriptive branch names such as:
```
feature/add-json-formatter
feature/add-dark-mode
fix/login-validation
fix/search-results
docs/improve-installation
test/add-note-tests
```
Avoid making changes directly on the main branch.

💻 Making Changes

Before opening a pull request:

Keep your changes focused.
Follow the existing project structure.
Follow the project's coding conventions.
Add or update tests when appropriate.
Update documentation when necessary.
Make sure existing functionality is not broken.
Run the relevant tests locally.
🧪 Testing

All relevant tests should pass before opening a pull request.

Testing instructions will be documented as the project develops.

📝 Commit Messages

Use clear and descriptive commit messages.

Preferred format:
```
type: short description
```
Examples:
```
feat: add snippet creation
fix: handle empty search results
docs: improve setup instructions
test: add note service tests
refactor: simplify resource service
```
Common types include:

```feat``` — new feature
```fix``` — bug fix
```docs``` — documentation
```test``` — tests
```refactor``` — code restructuring
```chore``` — maintenance
🔀 Pull Requests

When opening a pull request:

Explain what you changed.
Explain why the change was needed.
Reference the related issue when applicable.
Describe how you tested the change.
Keep the pull request focused on one purpose.

Example:
```
Closes #25
```
Pull requests may go through review before being merged.

Maintainers may request changes to improve correctness, maintainability, testing, documentation, or consistency with the project's architecture.

👀 Code Review

Code review is a normal part of contributing to DevVault.

Review comments are intended to improve the project and are not personal criticism.

Contributors are encouraged to ask questions and discuss alternative approaches when appropriate.

🏷️ Good First Issues

DevVault aims to provide beginner-friendly opportunities for new contributors.

Issues marked with:
```
good first issue
```
are intended to be suitable starting points for contributors who are new to the project or open source.

📚 Documentation Contributions

Documentation improvements are valuable contributions.

You can help by:

Fixing errors
Improving explanations
Adding examples
Improving setup instructions
Adding tutorials
Improving API documentation
🤝 Community Guidelines

Please be respectful and constructive when communicating with other contributors.

All contributors are expected to follow the project's Code of Conduct.

🔒 Security Issues

Please do not publicly report security vulnerabilities through GitHub issues.

See SECURITY.md for information about reporting security issues.
